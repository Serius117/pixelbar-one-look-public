# EDIFIER Halo PixelBar HID 协议（pixelbar-one-look 唯一权威）

> 迁移自前身项目（PixelBar 协议模块，2026-10-18 真机标定）。
> 来源：社区逆向（halo-pixelbar-mcp / claude-edifier-pixelbar-usage，MIT）+ TempoHub 1.3.1 厂商 App 抓包（USBPcap）交叉验证。

## 设备识别

| 项 | 值 |
|---|---|
| VID | `0x2D99` |
| PID | `0xA106`（亦有 `0xA160` 变体——两型号同协议）|
| HID 接口 | **interface 4 的 Col02**（usagePage `0xFF14`，唯一可写）；同一 interface 的 Col01(usagePage `0xFF13`) 写入报 `ERROR_INVALID_FUNCTION`（2026-11-16 实测）|
| Usage Page | `0xFF14`（厂商自定义）|

## 帧格式（host → device，64 字节 report）

```
2E AA EC <cmd> <len_hi> <len_lo> <payload...> <crc> <零填充...>
```

- CRC = 从第 1 字节（0xAA）起求和 mod 256
- 第三字节：工作代码用 **0xEC**（社区笔记写 0xED，实测 0xEC 正确）
- payload 最大 57 字节

## 命令表

| 命令 | 值 | 用途 |
|---|---|---|
| CMD_MOOD_QUERY | 0x6A | 查询灯效状态 |
| **CMD_MOOD_SET** | **0x6B** | **设置灯效（本插件核心）** |
| CMD_MOOD_RESET | 0x72 | 恢复出厂灯效 |
| CMD_VOLUME_QUERY | 0x66 | 查音量 |
| CMD_VOLUME_SET | 0x67 | 设置音量（0-16）|
| CMD_TEXT_QUERY | 0xE7 | 查文本 |
| **CMD_TEXT_SET** | **0xE8** | **推送文本（本插件核心，~2ms 实时）** |
| CMD_PIXEL_STATE | 0xEE | 像素状态 |
| **CMD_PIXEL_SET** | **0xEF** | **像素设置（布局/颜色/时钟/场景恢复）** |
| CMD_PIXEL_FILE | 0x17 | 位图文件推送（flash 资源上传，**弃用**：1.4s/帧非实时）|

## 0x6B 灯效（D38/D39 抓包标定成果）

Payload：`[light_array_index, light_index, R, G, B, brightness, speed, (mode)?]`

- `light_array_index`：设备自报（0x6A 查询，实测 0xA160 应答 0x20）；**错值被 ACK 但静默忽略**（社区笔记的 0x13 无效——实测教训）
- `light_index` = **效果选择器**（厂商 App 给每个效果一个专属灯区）：

| 灯区 | 效果 | R 载荷 | 语义（本插件状态映射）|
|---|---|---|---|
| 1 | 氛围呼吸 breathing | R/G/B=呼吸颜色 | 空闲 |
| 2 | 幻彩潮汐 tide | R=1 | — |
| 3 | 纯色静光 solid | R=1 或真 RGB | **失败（红色 RGB FF 00 00）** |
| 4 | 炫彩涟漪 ripple | R=0 | **完成庆祝** |
| 5 | 流光逐影 flow | R=1 | **执行中** |
| 6 | 动态光影 shadow | R=0 | **等待权限** |
| 7 | 总开关 | B=1/0 | — |

- 亮度 0-100（厂商 UI 上限；设备实际接受到 250）
- speed 255 = 保持现值；呼吸/潮汐厂商用 8
- **写入节律**：厂商单发；三连发（30ms 间隔）抗丢包无害（实测 2026-10-18）
- 厂商原始 payload 黄金样本（测试向量）：

```
breathing: [0x20, 0x01, 0x1C, 0xFF, 0xF8, 0x64, 0x08]
tide:      [0x20, 0x02, 0x01, 0x00, 0x00, 0x64, 0x08]
solid:     [0x20, 0x03, 0x01, 0x00, 0x00, 0x64, 0xFF]
ripple:    [0x20, 0x04, 0x00, 0x00, 0x00, 0x64, 0xFF]
flow:      [0x20, 0x05, 0x01, 0x00, 0x00, 0x64, 0xFF]
shadow:    [0x20, 0x06, 0x00, 0x00, 0x00, 0x64, 0xFF]
solid 红:  [0x20, 0x03, 0xFF, 0x00, 0x00, 0x64, 0xFF]（失败态示例）
```

## 0xE8 文本推送（D36 标定成果；PB.34b 宽度复测）

Payload：`[0x00, utf8_len, ...utf8_bytes]`
- **硬上限：48 UTF-8 字节**（2026-11-22 实测：18 个中文 54B 被设备截到 16 字 = 48B）
- **排版宽度：256px**（中文≈16px、ASCII≈9px；16 个中文正好满屏，40 位数字实测显示约 29 位）
- **16 字符不是硬线**，只是全角字符的近似：20 字符混合 `pixelbar-one-look 完成`（24B）可完整静态显示
- 宽度超出 256px → 用 `0xEF` 滚动模式承载全文（不按字符截断）；字节超出 48B 仍只能截断
- 20/20 ACK 实测，中位 1.9ms——唯一实时通道
- 中文/ASCII 均可；**Unicode 颜文字缺字**（仅 ASCII 颜文字可用，28/28 验证）

## 0xEF 像素设置（文本配套）

- 静态文本：`01 <R> <G> <B> 00 02 00 <align> FF`（align：0 左/1 中/2 右/3 撑满）
- 动态文本（右→左滚动）：`01 <R> <G> <B> 00 02 01 01 FF`（**宽度 > 256px 时用**，承载全文）
- 时钟（设备默认显示）：`01 <R> <G> <B> 00 01 00 00 FF`——**恢复默认显示需主动发本帧**；实测停推 0xE8 后设备**不会**自动恢复旧文字（2026-11-16 真机，推翻旧笔记的"10s 自动恢复"）
- 主题色：`03 <R> <G> <B> 00 00 FF FF FF`

## 设备响应帧（2F BB EC ...）

- 结构同 host 帧（首字节 0x2F）；解析出 (command, payload)
- 0x6A/0x72 应答：`[array_index, current_index, <6字节组>...]`——组内 `[index,R,G,B,亮度,speed]`，可解析总开关状态
- **0x6A 语义实测（2026-11-16，0xA160）**：查询帧空 payload 即可；应答 `array_index=0x20`、`current_index`=当前生效效果号（与上表灯区 1–7 一致）、后续 7 组为**各效果槽位保存的参数**（每组 index 1–7）。设置 0x6B 后复核：`current_index` 变为新效果号、对应槽位 RGB 回读等于所发值——可作写路径的机器验证。
- 应答样本：`20 01 | 01 C3B9FF 64 08 | 02 010000 64 08 | 03 FF3C3C 64 FF | 04 000000 64 FF | 05 010000 64 FF | 06 000000 64 FF | 07 000001 FF FF`
- **0x6B 回声**：每次 0x6B 写入设备回一帧 cmd=0x6B（三连发 → 3 条），与 0x6A 应答同队列——读应答时需按 cmd 过滤。

## 实施红线（前身项目踩坑总结）

1. **light_array_index 必须运行时查询**（0x6A），禁写死
2. **0x17 位图通道弃用**——flash 资源上传非帧缓冲（1.4s/帧 + 固件上传 UI）
3. **灯效为单选切换语义**（任一时刻一个活跃效果）
4. **HID 独占**：TempoHub 同时打开会抢占——插件应容忍设备打开失败（降级静默）
5. 文本 48 字节硬限 + 256px 宽度：超字节按字节截断，超宽走 0xEF 滚动（PB.34b 实测校准）
